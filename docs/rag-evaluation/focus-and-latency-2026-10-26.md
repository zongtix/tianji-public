按既定顺序继续：32题质量验收 → 针对样本修正回答 → 根据阶段记录判断耗时优化。32题单次来源初审通过不代表表达问题及稳定性已完成验收。本轮完成一个最小表达候选和12次真实对照，并补齐模型调用分类耗时。结论是：**保留当前C＋knowledge-v1；v4候选暂不默认启用，回答表达优化尚未通过整体启用验收。耗时优化优先关注回答生成，暂不改检索并发。**

## 单变量改动

`knowledge-v4-focused` 完整保留v1模板，只在末尾增加两句话：

> 仅回答用户本轮询问的事项，先给出结论、必要计算与来源。
> 补充内容只限会影响本题结论的条件或例外；不要主动列出用户未询问事项的资料缺口，也不要展开无关规则。

这轮没有复用v2/v3，也没有同时修改消息角色、授权、检索、重排、片段数、系统提示或生成参数。`KnowledgeAnswerPrompt` 增加显式版本选择，默认仍为knowledge-v1；新增测试验证v1原文完整保留、候选开销进入最终预算。文本进入模型请求的测试不能证明模型语义通过。

评测入口新增 `focus-control/focus` 冻结快照，见 [focus-experiments.json](focus-experiments.json)。原有generic `gen_ai.client.operation` 计时可能合并聊天与embedding调用，不能直接把该字段当作最终回答时间。本轮在每次已存在的模型用量记录中增加 `durationMs`，按模型种类和父阶段区分，用现有观测结束时刻计算，不增加任何模型调用或生产埋点。

## 耗时归因与决定

| 指标 | 原版 | 聚焦候选 |
| --- | ---: | ---: |
| 回答模型调用平均耗时（含网络与流式输出） | 1710.5ms | 1550.8ms |
| 向量路径平均耗时 | 399.2ms | 443.2ms |
| BM25路径平均耗时 | 86.0ms | 77.3ms |
| RRF平均耗时 | 2.0ms | 2.0ms |
| rerank平均耗时 | 239.2ms | 239.5ms |
| Advisor调用总耗时中位数 | 2705ms | 2563ms |
| 首个文本耗时中位数 | 1371.5ms | 1393ms |
| 6题聊天输入Token合计 | 7128 | 7416 |
| 6题聊天输出Token合计 | 1191 | 951 |

候选输出Token下降约20.2%，总耗时中位数少142ms，但首个文本中位数没有改善。每组单次6题、顺序执行、首题含初始化，模型及网络有波动，不能把全部时间差归因于模板，也不能声称生产提速。模型duration由实际观测计算，不是供应商纯推理耗时。向量路径已包含embedding，不将generic模型span、embedding和向量路径重复相加。

本批回答模型调用约占总耗时均值的60%—62%，是最大的已测组件。检索仍是串行向量、BM25、融合、重排，BM25均值仅约0.08秒；把两路并行时可能重叠的时间较小，还需维护取消与阶段有效性，因此本轮不引入新的并发编排。重排约0.24秒且此前有明确证据排序收益，继续保留。优先完善回答聚焦、确定程度和出处，再用同条件实验确认是否同时减少生成开销。

本批6题均无历史，未测多轮改写耗时。此前32题的points-31/32改写分别约850/682ms，原汇总按全部32题平均为48ms，不能用这个均值掩盖实际多轮请求开销。当前无足够证据支持减少必要改写调用。上述时间均为Advisor评测范围，不代表HTTP、路由、标题、记忆保存及浏览器端整轮时间。
