**这些指标不是事实充分性。** 初版片段标注并非最小充分集合：例如 points-26 标注了章节3和7，但章节7单独已可支持核心结论，因此 A 的0.5片段覆盖不意味着该例事实答错；points-04 即使命中两个标注片段，缺少章节2仍无法回答关键结论。逐例来源复核与片段指标分开记录，没有事后修改问题或标签来提高分数。

关键案例：

- **points-07（笔记18分再来3分）**：A为空召回；A′、B找回章节3并回答只补2分。
- **points-24（points_message/points_record）**：A为空召回；混合检索找回章节6，区分待发送消息与最终明细。
- **points-25（确认超时/NACK）**：A为空召回；A′、B找回章节7，回答sent保持0、可重试。
- **points-04（学习满50后签到/问答）**：A′扩大到6片段后包含关键章节2；B与B_CONTEXT前三仍是3、6、4，缺少按类型分别计额的关键依据。98.9%的平均片段覆盖不能掩盖这例缺口。
- **points-03（已明确学习45分）**：A和A′仍把已给定类型当成缺失条件要求澄清；B与B_CONTEXT给出5分，但附加了不必要的类型假设。扩大召回不能独自解决回答模型的条件理解问题。
- 两例无答案与含糊指代均保持保守回答/澄清，没有编造退款天数、价格或有效期；这不代表所有无答案场景都已覆盖。

B与B_CONTEXT每例最终选片完全相同。这份短资料未遇到预算裁减需求，**未测得上下文压缩或质量增量**；回答文字差异不能归因于上下文算法。没有为了展示收益制造冗余或改切分。

`reviews.json` 与逐例 answerReview 是 **Codex 来源初审**：A有6例主要缺口，A′、B、B_CONTEXT各1例主要缺口，另外标记了条件冗余、未支持的动机解释或章节引用等警告。这不是独立人工验收，也不是经人工校准的模型裁判评分；两者仍待完成，不把初审结果当作生产质量证明。

## 观测与用量边界

已接入真实 ObservationRegistry 的模型/向量存储，业务步骤覆盖改写、两路检索、融合、rerank、上下文及框架已有的生成观测。一个请求有独立请求ID，同会话通过langfuse.session.id关联；配置、实验和数据版本作为trace属性，不放高基数metrics标签。

本地 OTel span 测试验证 boundedElastic/SSE 下共同trace及成功、失败、取消都结束；本机OTLP/HTTP测试验证Basic Auth与请求载荷；Boot自动配置测试验证关闭默认OTLP地址后仍能使用自定义exporter。它们都**不等于 Langfuse真实查询验收**。当前没有可用实例与凭据，未部署新实例。

本次v1评测器只保存每例最后一次聊天模型回调的用量，可能覆盖多轮改写用量，未收集embedding用量。已记录末次调用的totalTokens分别为A 37636、A′ 62773、B 47142、B_CONTEXT 47202，**不能当作全链路成本或费用**。无模型调用的直接响应不伪造用量。本次运行未记录执行时Prompt哈希，代码版本仅有基线提交+未提交工作区标识，无法声称具有完整可复现实验清单。

后续运行器已补按父阶段分开记录聊天用量、Prompt哈希和版本字段，生产过滤器也把框架EmptyUsage标为缺失，避免把默认0当作实际用量。真实实验后另补了401/403终止识别、迟到取消错误丢弃及同步观测，并将来源与embedding模型纳入片段身份；当前资料为单一来源/模型，这两个身份字段不改变本轮去重或排序，多来源隔离由合成夹具验证。这些保护由本地测试覆盖，本轮没有超出获批次数追加模型请求。因此最终代码的正常检索/回答路径有本次真实证据，最后补充的保护与记录仍需下一轮获授权真实复验。

## 默认配置、回退与剩余工作
