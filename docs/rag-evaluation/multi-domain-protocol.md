# 多领域 RAG 对照评测协议

## 目标和现状

在原积分资料之外，增加一份可溯源的优惠券规则资料和 AI 设计的题目，检验不同资料、近义词、业务条件和无答案问题。题目不是用户日志或独立人工标注的泛化集。新增资料通过独立评测索引运行；正式聊天的公共库发布配置沿用现状。不得把积分固定集的旧成绩用于新语料。

2026-10-24 的固定集归档仅针对积分资料：A 原向量检索、A′ 扩大向量候选、B 混合检索。独立人工复核待完成，历史运行缺少提示词哈希等证据。C 的 32 题是后续单臂实验，不与 A/B 视为同批对照。数字和限制见 `docs/aigc-rag-optimization-report-2026-10-26.md`。

## 数据准备及边界

1. 将资料逐条对照业务源码和对外口径，记录来源、版本与核验日期；业务动态价格、库存及用户个人数据由业务接口确定，不从静态知识中推断。
2. 冻结经审核的资料版本及哈希；用生产切分器离线生成文档、章节和真实片段映射，复核切分前后含义。不得把章节序号猜成片段号。
3. 依据冻结资料准备题目和必要证据标签，包含多文档干扰、同义表达、多跳条件、否定、追问和无答案。记录题目来源和标注者；从调参数据中分离最终测试集，题目与标签在比较前冻结。若无法独立标注或复核，明确说明，不称盲测或真实用户样本。
4. 积分与优惠券的授权范围必须明确。不要为了对比将优惠券静默放入积分会话白名单；需要跨文档干扰时，使用明确授权的评测范围。本次依据会话中的实施授权及“继续”指令，将两份仓库规则资料发送至既有 embedding/chat/rerank 服务，索引使用 `tj_aigc_eval_` 前缀；不得覆盖原有索引或用户数据。

## 方案与指标

同一批次固定资料和索引快照、问题及标签、授权范围、模型和提示词、运行环境，仅改变指定的检索策略：A 原向量参数；A′ 扩大向量召回；B 向量 + BM25 + RRF；C 在 B 上加重排。各方案必须按实际状态报告；重排失败回退不可冒充正常 C。保留每路候选、最终选片及来源身份，并记录错误、降级、阶段耗时、可获得的模型用量。

分开报告候选阶段的标注证据召回、最终上下文的标注证据覆盖、排序质量、无答案或澄清的正确处理，以及对回答的事实依据、关键条件和引用人工复核。明确每个指标的公式、分母和样本量；缺少真实候选或人工审核时标为未评，不推算成功。召回和覆盖都不等于回答正确率。记录每题差异，按场景和资料分层；样本太小不作总体或生产性能推断。耗时和成本的对比应列出范围、缺失用量与外部模型波动，不能将总延迟差全部归因于某一模块。

## 当前可执行的离线对比

`python -X utf8 scripts/rag-evaluation/compare.py docs/rag-evaluation/results/A.json docs/rag-evaluation/results/B.json`

此命令只读取两个现有报告，输出配对案例的最终上下文证据覆盖差、每例变化与耗时中位数，不访问服务，不生成新的模型回答或新的检索结果。它拒绝案例集合、数据集版本、提示词哈希等明确不一致及失败/降级的报告，但相同案例 ID 不证明题目、标签、索引快照和运行环境相同。缺失字段会警告，必须结合完整实验清单和原始数据人工核对；它不是统计显著性检验，也不替代人工回答评审。

## 可复现的多文档运行

`prepare.ps1 -Output target/rag-optimization/<dataset> -Index tj_aigc_eval_<batch>` 仅离线调用生产切分器，输出 `dataset.json` 与 `corpus.json`。它保留原积分 32 题作为回归数据，加上优惠券 12 题；所有案例均明确授权两个文档，允许跨文档检索干扰。优惠券参考证据通过原文锚点映射至真实片段；无答案题的证据分母为空。草稿源文件继续保留章节引用和未独立人工验收的状态。

`run.ps1 -Mode A -Answers -Dataset <dataset.json> -RunGroup <batch> -InitializeCorpus` 只允许初始化全新的 `tj_aigc_eval_` 索引。后续 A′/B/C 使用同一数据集和批次，不加初始化参数。已有索引不被覆盖；后续每组校验片段数量并记录索引内容快照，执行结束确认内容未变。原 ES 应用账号无手动 refresh 权限，初始化等待自动刷新，不扩大账号权限。

`report.py <dataset.json> <reports-directory> --output <new-summary.json>` 严格检查数据集字节哈希、索引快照、源码版本、提示词、模型、生成参数和案例集合，拒绝错误或降级数据，依据完整证据身份重算候选与上下文覆盖。候选覆盖使用各模式配置的实际候选深度，不称统一的 Recall@K。`compare.py --strict` 提供同样的配对检查；旧报告缺少必要指纹时只可在非严格模式查看历史统计。

每次正式运行保留原始逐题报告、资料与数据集哈希和源码文件清单。新增语料改变索引内容及 BM25 统计，因此该批结果独立归档，不能和旧单文档结果直接作因果对比。资料规模仍然很小，回答质量另做语义审核，明确 AI 初审与人工复核的区别。
