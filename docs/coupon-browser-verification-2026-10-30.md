## 页面验收阻断：我的优惠券分页缺失

- 调用方：`D:/Java/tj-protal/src/api/class.js:115` 的 `getMyCoupon` 调用 `GET /prs/user-coupons/page?status=1&pageNo=1&pageSize=1000`。
- 服务端：`tj-promotion/src/main/java/com/tianji/promotion/controller/UserCouponController.java:23` 下只有领取和兑换 POST，没有对应 GET 分页映射；其他促销 Controller 也未提供此路径。
- 实际响应：HTTP **200**，业务 `code=500`、`msg=服务器内部异常`，没有 `data.list`。不能因为 HTTP 200 就判成功。
- 促销日志明确记录 `NoResourceFoundException: No static resource user-coupons/page.`，由现有全局异常处理包装为上述业务错误；不是本次异步消息或兑换事务失败。
- 用户影响：即使异步兑换成功且券已真实落库，个人中心仍无法刷新券列表，会出现服务器异常提示。因此不能宣称已完成用户可用的页面全闭环。
- 本次处理：记录问题，不替换成假列表、不把成功消息改成失败、不扩展实现新接口。
- 建议下一步：补齐登录用户自己的优惠券分页查询，兼容现有状态筛选、分页和展示字段，再复验兑换成功后的列表更新；不应先扩展交易核销。
