# 长期记忆与 Langfuse 内容采集

默认配置关闭以下三个开关；local profile 显式开启，以便在本机 Langfuse 查看日常追踪内容。它们只决定本应用添加到观测中的内容，不修改聊天、提取或数据存储逻辑。用户级长期记忆关闭也不等于关闭遥测正文；应分别配置。

```properties
tj.ai.observation.conversation-content=false
tj.ai.observation.memory-details=false
tj.ai.observation.model-content=false
```

- `conversation-content`：在 `chat.request` 记录本轮用户问题和已经生成的回答；取消时可能只有部分回答。输出不包括课程卡片。字段是 `langfuse.observation.input/output`。记录的是用户与助手的正文，回答仍可能复述记忆。
- `memory-details`：在聊天观测中记录读取到的记忆类别和内容，在异步 `user_memory.extract` 观测中记录模型产生的候选内容；候选不代表已通过校验或已保存。即使关闭详情，存在读取记忆时也会记录类别，提取观测会记录候选数量和结果。异步提取使用同一个 `langfuse.session.id`，不保证是同一个请求的子 span。
- `model-content`：记录模型输入、输出及工具参数、结果，单条属性超过 8000 字符时截断。模型和工具内容不会经对话正文过滤，可能包含系统提示、历史、记忆、工具数据和敏感信息；仅在可信的 Langfuse 环境开启。

正文和记忆详情开关对命中现有敏感信息规则的整条文本使用占位符，并对单条文本限制长度；规则只能覆盖部分格式，可能漏拦或误拦，不能当成匿名化保证。对合成评测，准备专用数据库、Redis、账号和 Langfuse 项目，并且只发送合成内容。常规环境根据数据管理要求谨慎启用正文及记忆详情。

开关在启动时读取，仅影响启用后产生的新追踪，不能补回旧追踪。内容采集不保证每次导出或每种节点都有完整正文；例如空响应、截断及异步导出失败都会影响结果。

长期记忆启用时仍必须保持 `spring.ai.chat.observations.log-prompt=false` 和 `log-completion=false`；它们会触发 Spring AI 的内容日志，不能用它们代替新的独立开关。改动这些配置的生效方式取决于实际配置来源；上述字段为启动时注入，修改配置后需在受控环境重启服务。请同时检查其他日志、代理和遥测路径。

## 2026-10-28 本地验证

在本机 Langfuse 新建独立项目 `tianji-memory-synthetic-eval`，使用合成问题和合成记忆进行验证。测试使用真实 `ChatServiceImpl`、观测过滤器和 OTLP 导出器，但身份、模型和记忆存储使用测试替身；没有调用真实模型或业务数据库。通过测试项目的实际页面确认：默认关闭时，请求的正文和记忆详情没有显示；开启合成采集时，`chat.request` 显示合成问题、回答和读取的合成记忆，模型节点显示合成输入输出，`user_memory.extract` 显示合成候选和处理结果。异步提取以相同会话 ID 关联，未验证同一父子 trace。本次一次性测试密钥均已撤销，项目及合成 trace 保留。

本地 OTLP 接收端、观测及导出测试共 13 项通过；独立项目的合成导出测试通过。这一组测试通过代码设置开关和替身，不代表日常运行服务已更新，也不覆盖真实认证和真实模型。失败、停止和敏感内容主要由本地测试覆盖，尚未在实际 Langfuse 页面逐项复验。本实现不创建 Langfuse 数据集或评分器。
