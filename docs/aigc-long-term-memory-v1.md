# 学员跨会话记忆 V1

## 范围和接入

默认关闭。启用后，普通对话的正常完成轮次会在后台尝试提取用户明确表达的学习基础、学习目标和学习偏好。同类可以保存多条独立事实，每条最多 160 字，每用户最多 30 条；达到上限时保留已有内容，不再新增，仍可纠正或删除。用户在助手的「我的记忆」中可以查看、纠正、逐条删除、删除全部和关闭自动记忆；删除记忆不删除会话记录，删除会话也不会自动删除已经整理好的长期记忆。再次在新对话中分享相同信息时，它仍可能被重新记录。

这不是 Hermes 的全局单人文件：长期记忆和提取任务均以认证后的 `userId` 限定，内容分别保存到 MySQL 的独立表，不加入 `MessageChatMemoryAdvisor` 的对话消息或 RAG 知识库。普通对话读取当前用户的三类记忆，作为低可信背景传给路由和业务智能体；当前表达优先，课程事实仍由现有课程工具提供。绑定知识库的会话不提取或注入长期记忆。没有新增 Redis 缓存或 ES 索引，因此 V1 的删除无需跨缓存、索引同步。

## 完成与后台处理

1. 正常对话开始时写入加密的 `WAITING` 轮次；问题超过 3000 字或命中敏感信息规则时不排队。只带上一条以问号结尾的助手问题作为短回答的上下文。
2. 最终回答流正常完成且生成占位仍活跃时，内部 Advisor 附加不可见请求标记。MySQL 会话窗口和任务转 `PERSISTED` 在同一事务中提交；此状态不能被提取工作者领取。整轮完成后，Redis 对同一请求原子决定完成或停止：完成封存胜出才转 `READY`；停止胜出则清理待确认任务。封存之后的带请求 ID 停止会返回该轮已结束，现有学员端使用该带请求 ID 的方式。旧版不带请求 ID 的停止接口没有结果标识，封存后不生效时仍可能返回常规成功。失败或断连走清理路径；交接失败回滚联合事务并单独重试会话窗口，该轮记忆允许丢失。这里的完成边界是服务端整轮处理完成，不是客户端确认收到每个字节。
3. 后台按同一用户、同一会话和同一代次合并：满 3 轮或等待约 30 秒后尝试处理，最多两条工作线程。一次调用共享的聊天模型，输入为最多 3 轮和已有记忆及其 ID，输出最多 2048 tokens、9 条候选事实，响应文本上限 8192 字符；稀疏对话可能每轮产生一次调用，具体费用取决于供应商和实际 token。提取使用流式响应及 `stream_options.include_usage`，此前 DeepSeek 测试支持，多事实提示词尚需真实模型复测，切换供应商时需验证兼容性。整体等待上限为 45 秒，超时会取消订阅并重试；若自定义模型在创建或订阅流时同步阻塞，无法保证取消能终止底层调用。无需调用课程工具或改变业务 Agent 的 ReAct 流程。
4. 结果必须带有来源请求 ID 和用户问题中的连续证据片段，通过类别、长度、敏感词、版本及代次检查后写入。`targetId=null`（或缺省）只新增独立事实；更正必须指定当前用户提取快照里同类别的已有 ID，不能按类别覆盖。完全相同或仅空白、大小写不同的内容由服务端去重；语义重复由模型结合已有事实判断，不保证完全识别。并行写入改变快照时重新提取，旧来源不能覆盖同条事实的新来源。证据校验不能证明模型总结或更正判断一定正确，用户仍需能纠正。
5. 提取最多尝试 3 次（首次加两次重试），仍失败会转为 `FAILED`，加密内容保留到 24 小时后由后台轮询清理；用户删除、纠正或关闭时仍会清理其任务。`FAILED` 的 `next_attempt_at` 表示保留期限，不能被普通领取；目前没有管理界面或自动重放，需要受控运维处理。`WAITING` 和未封存的 `PERSISTED` 超过一小时会被清理，领取租约 2 分钟到期后可重新领取。进程在完成封存与 `READY` 写入之间崩溃时，可能漏记该轮，但不会将未确认轮次当作成功提取。领取事务使用 `READ_COMMITTED` 并对锁冲突做有限重试；若应用关闭或数据库不可用，过期记录只能在后台恢复运行后清理。单进程重启后 `READY` 和过期租约可再次处理。

用户纠正、删除或关闭自动记忆时，数据库事务同时增加该用户的代次并删除其待处理任务；已经领取的旧任务不能再次写入。删除某个会话时，该会话的待处理任务也会失效。对已经发送给模型或正在生成的请求无法撤回已发送内容；更改和关闭影响之后读取的请求，正在使用旧快照的对话可能已经收到它。

## 启用前准备

新库执行 `tj-aigc/src/main/resources/db/user-memory.sql`；已存在旧 V1 表时执行一次 `tj-aigc/src/main/resources/db/user-memory-multi-fact-migration.sql`，不会自动执行迁移。迁移去掉 `(user_id,memory_key)` 唯一约束，改为普通索引，原有 ID、密文、版本、来源及旧摘要全部保留，不自动拆分。准备独立的测试环境并完成 MySQL 备份、权限和迁移审核后再运行。脚本为新表创建队列清理和租约索引；如果表已经存在，`CREATE TABLE IF NOT EXISTS` 不会补建新增索引，需先检查实际索引。

迁移时停止全部 AIGC 实例的记忆读写，再执行索引迁移，最后统一启动多事实版本；不能混跑旧版本，也不能在同类出现多条事实后直接回滚旧代码。旧摘要后续只在明确更正时按 ID 更新，并需保留其中未被更正的事实。已经被旧代码覆盖的内容不在当前记忆表里，本次迁移不能自动恢复，需根据用户原话重新确认。V1 要求原有会话记忆选择 MySQL，MongoDB 模式不支持启用。

通过安全的部署密钥管理提供以下配置；不要把密钥写入仓库或日志。所有实例及恢复环境必须使用相同的稳定密钥，丢失密钥将无法解密旧数据；V1 尚无密钥轮换工具。

```properties
tj.ai.long-term-memory.enabled=true
tj.ai.long-term-memory.encryption-key=<Base64 编码的随机 32 字节密钥>
spring.ai.chat.observations.log-prompt=false
spring.ai.chat.observations.log-completion=false
```

这两个内容采集开关当前在项目 `application.yml` 中为 `true`，启用长期记忆前必须在实际配置来源中显式覆盖为 `false`。程序会检查此条件，禁用带完整 prompt 的 `SimpleLoggerAdvisor`，否则拒绝启动。需另外检查运行环境的 HTTP 调试日志、代理、模型供应商和其他遥测配置；这两个开关本身不保证外部系统不会采集内容。现有 `langfuse.session.id` 仍是原会话标识格式，没有改造成匿名标识。

全局功能启用后，未设置过的用户默认开启自动记忆，应在面向学员开放前提供清楚的告知并确认平台隐私政策与模型处理方式。规则过滤只覆盖部分联系方式、凭证等明显形式，不保证识别所有敏感信息。应用内的 AES-GCM 加密不替代数据库访问控制、传输保护、备份保留策略或密钥管理。

## 管理接口

所有接口从 `UserContext` 获取身份，不接受客户端指定用户 ID，沿用已有网关身份传递和响应包装约定；服务本身需处于可信网络，不能把内部 `user-info` 请求头当作对公网的认证手段。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/memories/settings` | 读取本人开关 |
| PUT | `/memories/settings` | 设置 `{ "enabled": true/false }` |
| GET | `/memories` | 读取本人记忆，ID 以字符串传输 |
| PUT | `/memories/{id}` | 用 `{ "version": 版本, "content": "内容" }` 乐观锁纠正 |
| DELETE | `/memories/{id}?version=版本` | 乐观锁删除一条 |
| DELETE | `/memories` | 删除全部并取消待处理任务 |

## 验证和后续评测

多事实改动在本地通过 147 项后端回归，包括跨会话追加、同批同类多事实、按 ID 更正、去重、旧摘要及密文保留、并行快照重试、旧来源防覆盖、越权和容量边界，以及课程智能体注入和停止链路。迁移脚本在 H2 MySQL 模式下执行验证；前端记忆 API 3 项测试和记忆面板 Vue 编译通过。本次未执行业务 MySQL 迁移、重启日常服务或调用真实模型，不能据此认定运行环境已生效或模型语义质量已验收。

隔离验收使用了独立 MySQL 8、Redis 7、模拟身份网关和模型，也以固定合成样例调用 DeepSeek 检查提取和 token。它们不能代替正式网关认证、真实学员的隐私告知、多轮客服质量及大规模并发评测；小样本用量也不能推断生产费用。`UserMemoryRealInfrastructureTest` 和真实模型评测测试均由专用环境变量显式开启，实际库测试会清理指定的隔离测试库，不能指向日常数据库。ES 语义召回与索引一致性属于后续阶段，当前没有实现。
