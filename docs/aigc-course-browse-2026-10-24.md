# 泛化课程浏览与热门推荐入口（2026-10-24）

## 问题与结果

原问题“有哪些热门课程推荐？”曾将“热门”作为课程名称关键词，又把泛化需求送入语义搜索，最终向用户汇报空列表与演示候选，要求先说明学习目标。原工具只支持名称和目标检索，未接入业务搜索已有的报名量排序能力。

现在课程推荐分支提供 `browseCourses`，接住热门推荐、随便看看、免费课浏览和“不知道学什么”。先展示有内容依据的课程与卡片，再询问一个感兴趣的方向。具体学习目标仍使用原语义检索，课程名称查询和咨询工具边界保持原有模式。

最终真实问答中，热门、随便推荐、不知道学什么均展示前端与微服务两门原有课程；两门的报名量记录均为零，因此明确作为课程浏览，不称为热门榜单。免费课现有资料不足以支持推荐时，如实说明，没有拿演示课程补位。

## 实现

- 搜索服务新增只读接口 `GET /courses/popular`，支持可选 `free` 与 `keyword`，固定按 `sold` 降序、ID 升序取最多 20 条，仅返回课程 ID 和报名量；没有报名量保留未知，查询失败不伪装为空结果。接口不依赖教师、兴趣或登录用户画像。
- `SearchClient` 与 `CoursePopularityDTO` 提供相同调用协议。这里只读取既有业务搜索索引，不写课程、报名量或向量。
- 浏览工具再次读取课程服务，核实状态、售卖时间、免费限制及价格；批量获取当前详情，过滤明确的 `【AI演示】`、`AI联调演示数据`、`不提供真实授课` 标记，最多向模型提供 10 门非演示候选。最终仍最多 3 张卡片，由原 `recommendCourses` 再次核实在售状态与价格。
- `hasEnrollmentData` 只表示本轮可用候选中存在正报名量，不能替最终选择背书。模型还须核对最终选中课程各自的报名量；零或未知报名量不能称为热门，不把报名量解释为近期趋势、口碑或教学质量。
- 介绍只有口号或占位内容、目录与人群也无法支持教学主题时，提示词要求跳过。该资料质量判断由模型执行；演示标记和在售条件由工具过滤。泛化浏览不要求先提供基础或目标，不展示工具名、检索方式、空列表等内部过程。
- 浏览正文聚焦课程内容，价格及有效期交由卡片展示。明确追问时逐门对应本轮结果，不将某门的数值套用其他课程，也不推断起算时间。

## 验证

JDK 17 下，搜索、浏览工具、既有名称/语义推荐、工具准备、路由、卡片与历史共 10 个测试类、110 项相关测试通过，无失败或跳过。搜索和 AIGC 打包成功。候选窗口及最终提示词调整后，相关 52 项再次通过并打包；与前述测试有重叠，不累计。日志：

- `target/course-browse-regression.log`
- `target/course-browse-workflow.log`
- `target/course-browse-refinement.log`

通过真实搜索服务、课程服务与现有模型服务完成 6 轮 SSE 问答：四种开场“有哪些热门课程推荐？”、“随便推荐几门”、“有什么免费课”、“我也不知道学什么”，以及单门、多门价格与有效期追问。63 项脚本检查通过，并单独审阅正文与卡片依据；未使用模拟模型或业务响应。

卡片与当前课程接口的名称、价格、有效期、状态一致；追问保持课程归属；每轮仅一个结束事件，卡片在结束前；历史只保存原问题、可见回答及对应卡片。最终四个测试会话按本次创建 ID 和完整问题序列核对后删除，使用独立合成用户，未操作日常用户会话。

复验命令：

```powershell
python scripts/local/verify-course-browse.py --real-model
```

该脚本会向当前模型服务发送合成问题及课程工具结果，创建并清理专用用户 `900000000000000024` 的会话。报告为 `target/course-browse-live/report.json`，包含完整回答、卡片、课程事实与清理记录；免费课程原始依据另存 `free-source-review.json`。

## 保留的失败与边界

首轮协议检查通过后，内容审阅发现模型推荐只有口号的“课程2”，并在另一轮把 12 个月套用到实际为 9999 个月的前端课程。原问答保存在 `report.first-content-review.json`，未作为最终内容通过样本。

第二轮发现 5 个候选名额被资料空泛的记录挤占，微服务课未进入候选，因此扩大到 10 门；还收紧最终选中课程的热度说明。免费问题没有卡片符合当时真实资料情况，原脚本却要求每轮必须有卡片，已纠正这项验收条件并独立核对免费课程资料。该轮记录保存在 `report.second-content-review.json`。

首轮验证覆盖本地真实服务与 SSE，未新增浏览器点击验收；没有运行仓库全量测试。最终两门课程的有效期都为 9999 个月，多门追问通过不能据此证明不同有效期的所有表述均正确。现有课程中仍有占位介绍和目录质量问题，不能由在售状态或报名量推断教学质量。

本地搜索 `8083` 和 AIGC `8096` 在功能初验时已按原启动配置加载本次改动。没有修改课程资料、索引内容或全量同步开关；本轮改动仅做本地提交，不推送。

## 补充验收与定向修复

随后使用真实模型、搜索和课程服务补充 8 条问题，分别覆盖热门浏览、模糊目标、多条件选课、上下文追问、两门课程比较、无合适课程、教学服务资料缺失及免费限制。8 轮 SSE 正常结束，返回卡片的名称、价格和有效期与当前课程接口一致，7 个专用会话的历史问题、回答和卡片核对一致。内容审阅有 6 条通过、2 条失败，未把协议通过当作内容全部通过：

- 免费 Java 推荐仍发送了「java泛型」卡片。其详情为「课程详情」、人群为「适用人群」，目录无法支持泛型教学内容；回答还解释了演示候选的排除过程。
- 核反应堆中子输运计算问题未找到匹配课程，却进一步断言平台没有核工程或反应堆物理相关课程，超过本次检索依据。

针对这两点，仅收紧推荐与最终回答提示词：提交卡片前须有与目标对应的具体内容依据，课程名、免费和报名量不能替代依据；不能先发卡片再让用户核对；无结果只说明本次未找到；不展示演示数据或内部筛选过程。资料质量判断仍由模型执行，未新增程序化质量评分或修改课程资料。

修改加载到本地 `8096` 后，使用原来的免费 Java、核工程两个问题和一个正常微服务选课问题完成 3 轮定向复测：前两轮均未发送卡片，未暴露内部筛选过程或断言全平台无相关课程；正常推荐仍返回符合 200 元预算的 199 元微服务课程。三轮 SSE、当前卡片字段、历史保存及会话清理均核对通过。该结果是有限样本验证，不保证所有问法均正确，没有重复运行全量测试。

另在真实网站经登录、网关及实际模型完成推荐和追问两轮浏览器验收。卡片实际点击打开对应微服务课程详情并显示 199 元；单独核对前端课详情 149 元及 JavaScript 目录；刷新后原问题、回答和课程卡片恢复正常。浏览器 13 项检查通过，原有 78 个会话保留。补充验收的 7 个合成会话、浏览器 1 个会话及修复复测的 3 个合成会话均按本轮归属核对后清理。
