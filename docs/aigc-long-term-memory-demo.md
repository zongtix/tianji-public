# 跨会话长期记忆：项目演示记录

目标是为实习面试提供一条能运行、能解释的功能链路。2026-10-28 在本机隔离环境完成了学员页面到后台的合成对话演示；这不是正式部署，也不是完整生产验收。

## 演示结果

使用实际学员页面、独立 MySQL 和 Redis、合成用户，模型提取和生成回答调用 DeepSeek `deepseek-flash`。身份由本机测试代理映射，意图路由和会话标题由测试替身提供，Nacos 服务发现及正式认证未参与。

1. 用户依次说自己用 Java 写过两个月小练习、想学习后端开发、喜欢文字教程。
2. 页面「我的记忆」展示了三条相应的学习基础、目标和偏好。截图为 `target/memory-demo-20261028/memories.png`，位于构建产物目录，清理时可能消失。
3. 新建会话询问先前的编程基础，页面回答「你之前自述：用 Java 写过两个月小练习。」
4. 在页面中将基础纠正为「学过 Java，目前正在练习」，随后删除全部，面板显示没有记忆。

最初的浏览器脚本在新会话创建期间过早检查答案，误报失败；随后查看页面并继续完成纠正和删除。这个结果来自一次连续页面操作，但不是一次无中断的自动脚本通过。后台独立 HTTP/SSE 测试也用真实模型跑通了提取、跨会话回答、纠正和删除；另有前端记忆 API 3 项测试通过。

浏览器演示阶段有 6 次真实模型调用，供应商返回的用量为输入 3,739、输出 582 token，全部内容为合成数据。此前同轮后台 HTTP 测试发起 5 次模型调用；该次采集器重复统计了流中用量，无法可靠报告其 token 总量，不能与浏览器数字相加。已修正测试采集器以按每次调用记录一次用量。

## 面试时可以怎么讲

- **问题**：原有会话记忆主要服务当前会话，新会话可能重复询问学员的基础和目标。
- **方案**：在对话正常完成后异步提取用户明确表达的信息，存为用户级的基础、目标和偏好；新会话按用户读取，作为低可信背景交给助手。
- **工程取舍**：V1 使用 MySQL，每类一条，容易查看和纠正；与会话消息、RAG 分开，不新增向量库。异步提取不阻塞正常回答，停止或失败的轮次不应作为已完成轮次提取。
- **用户控制**：提供查看、纠正、删除和关闭；用户更改操作会使旧的待处理任务失效，避免旧结果覆盖用户修改。
- **局限**：模型可能提取错误；每类一条表达能力有限；敏感信息过滤是规则筛查，不保证覆盖全部情况。当前演示的认证和路由使用替身，不代表生产认证或正式发布已经完成。
