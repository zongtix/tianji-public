目标：为“根据学习目标找课 → 查询课程详情 → 展示推荐卡片”提供可区分的数据，后续用于课程语义检索联调。

2026-10-22 对现有 `tj_course` 的只读核对：14 门未删除课程，其中 12 门上架、2 门下架。虽然均有 `course_content`，但多数是“课程1”等占位内容，只有 2 门的详情超过 50 字，无法充分验证学习目标与课程内容的匹配。

## 写入方式

使用现有 Nacos `shared-mybatis.yaml` 的连接信息，只允许访问 `tj_course`。凭据通过标准输入传递，不打印、不写入 Git。需要 Python 和 PyMySQL。

```powershell
# 只读检查分类、字段和 ID 冲突
./scripts/local/seed-ai-courses.ps1
# 在事务内插入并验证，最后回滚，不保留数据
./scripts/local/seed-ai-courses.ps1 -Rehearse
# 核对通过后，一次事务提交
./scripts/local/seed-ai-courses.ps1 -Apply
```

一次准备 6 张表：`course`、`course_draft`、`course_content`、`course_content_draft`、`course_catalogue`、`course_catalogue_draft`。正式数据和草稿使用相同课程、内容和章节；复用现有启用分类及一张课程封面，不创建教师账号或虚构视频。章节仅为内容大纲，没有可播放小节，`section_num` 和时长均为 0。

脚本只插入缺失记录。重复执行时逐字段核对并跳过相同记录，遇到 ID 冲突或被编辑过的数据则拒绝覆盖。插入失败回滚整个事务；提交前校验原有记录内容未变。执行报告在 Git 忽略的 `target/ai-course-demo/`。

直接写库不会触发上架 MQ，也不会自动刷新课程关键词索引或生成向量。数据库样本准备好，不代表当前助手已经能检索到它们；后续课程索引接入时需要单独验证。

2026-10-22 后续课程向量入库、推荐工具接入及演示课程名称索引补齐已完成：10 门有效演示课程进入独立 ES 课程向量索引和既有关键词索引 `course`，下架和过期样本跳过。推荐按学习需求调用语义检索，明确名称仍走既有名称搜索。执行方式和分阶段验证边界见 [课程语义检索说明](../tj-aigc/course-retrieval.md)。

## 补齐演示课程名称索引

先恢复本机课程、搜索、交易服务及 ES 隧道，再执行：

```powershell
# 只读检查有效演示课程与现有关键词文档
./scripts/local/sync-ai-course-keywords.ps1
# 仅创建缺失文档，不覆盖已有文档
./scripts/local/sync-ai-course-keywords.ps1 -Apply
```

脚本限定固定的 12 个演示课程 ID，从当前课程服务的 `simpleInfo/list` 和 `searchInfo` 读取状态、购买时间和索引字段；按上海时区将发布时间转换为 ES 日期映射使用的毫秒值。下架和过期样本不写入。它复用现有 `target/aigc-es/private/search-password.txt`，凭据通过标准输入传递，不输出到报告。

写入使用 ES `_create`，已有不同文档直接拒绝覆盖；写前保存有界索引快照，写后验证原有文档摘要、演示文档和名称查询。中途失败只按序列号和主分片任期回滚本次新建文档，避免删除并发修改。报告与快照在 Git 忽略的 `target/course-guide-daily/keyword-sync/`。这是演示数据补齐脚本，不承担正式课程的更新、下架或删除同步。

实际写入新增 10 条，索引由 12 条增至 22 条，原有 12 条未变；重复执行新增 0 条。电脑重启后再次只读核对，22 条仍在，10 门有效演示课程无缺失。独立名称比较及学习需求推荐的浏览器观察记录见上述课程语义检索说明。

## 后续检索验收场景

- “我刚开始学编程，不会 Java”：应优先匹配入门课程，不应直接推荐并发、微服务。
- “我学过 Java 基础，想学习线程池和高并发”：并发课程应成为合适候选。
- “订单列表查询太慢，怎么定位索引问题”：MySQL 课程应成为合适候选。
- “课程详情访问量很大，想减轻数据库压力”：缓存课程应成为合适候选。
- “消息重复消费导致积分加了两次”：可靠消息课程应成为合适候选。
- “想批量整理 Excel 文件”：Python 自动化应成为合适候选。
- 下架与过期样本即使命中，也必须在业务数据复核后排除。

这些是待验证的业务预期，不能视为模型或向量检索已通过的结果。
