# 支付宝 MCP 沙箱购买验收

2026-10-27。本机最小购买流程已完成验收：助手课程卡片 → 服务端核价预览 → 用户明确确认 → 业务订单 → 官方支付宝 MCP 网页支付链接 → 沙箱收银台 → 服务端查单。用户在自动联调之后明确反馈“我已实测验收成功”，据此记录沙箱付款与查单的人工验收通过。

## 实现范围

- `tj-trade/.../sandbox/`：独立、默认关闭的沙箱入口。复用 `IOrderService.placeOrder` 和课程服务价格；确认令牌绑定试点用户、课程和金额，有效期 10 分钟，Redis 分布式锁保护重复确认。
- 固定官方 MCP `2.0.0`，通过 stdio 调用两个工具。子进程环境强制 sandbox、只开放网页支付和查单、禁用日志；校验返回网关、APPID、订单号和金额。
- 金额以整数分保存在订单中，以十进制数元传给 MCP。官方工具 `totalAmount` 的 Schema 为 number，不能传字符串。
- 旧课程允许未设置购买开始时间；若显式设置未来开始时间仍拒绝，缺失或过期的结束时间也拒绝。
- 前端只在独立开发试点启用；在课程卡片提供沙箱购买确认弹窗，展示服务端金额并手动打开收银台、手动查单。
- 支付凭据和签名链接不进入模型提示词、聊天历史或模型工具调用。本次没有新增模型请求。

沙箱虚拟资金不触发真实履约。查单不会将普通订单标记为已支付，不调用 `handlePaySuccess`，不发布课程开通消息。因此这项结果可表述为“支付宝 MCP 沙箱购买与查单集成”，不能表述为正式支付上线或真实付费课程开通。

## 实际验证

| 检查 | 结果 |
| --- | --- |
| 后端专项测试 | 13 项本地测试通过，另 1 项真实 Java SDK 只读查单通过，共 14 项 |
| 前端专项测试 | 沙箱开关、链接、代理路由及既有卡片/试点测试共 16 项通过 |
| 构建 | `tj-trade` 及其所需模块 package 成功；Vue 构建成功，输出到后端 target，未覆盖前端 dist |
| 实际订单 | `2114982826720903169`，Java程序员的前端课程，14900 分；试点账户下由 0 笔变为 1 笔 |
| 明确确认 | `confirmed=false` 返回 400；只预览或关闭弹窗不调用创建支付工具 |
| 重复确认 | 同一确认信息复用订单及同一链接，数据库中仍为 1 笔订单 |
| 沙箱收银台 | 浏览器打开签名链接后进入 `excashier-sandbox.dl.alipaydev.com`，显示正确课程与 149.00 元，无错误页 |
| 自动联调时的查单 | 当时返回 `NOT_CREATED`（支付宝 `ACQ.TRADE_NOT_EXIST`），自动联调未登录买家或付款；这是人工验收前的历史结果 |
| 自动联调时的业务订单状态 | 当时为待支付 `1`，金额 14900 分；沙箱查单不改变正式订单的履约状态 |
| 后续人工验收 | 用户反馈“我已实测验收成功”，沙箱付款与查单验收通过；未提供具体成交订单号或状态原文，不将该反馈绑定为前述测试订单的新查单结果 |
| 访问边界 | 非允许课程/账户、跨来源请求均 403；退款路由和原 18084 试点支付路由均 404 |
| 生命周期 | Stop 后仅结束两个持有进程；重新 Start 和 Check 通过，原课程试点继续可用 |

Windows Java 17 的测试 JVM 默认编码曾导致中文 MCP JSON 无法解析；改用 `-Dfile.encoding=UTF-8` 后真实查单通过。运行脚本固定此参数，适配器也在非 UTF-8 环境拒绝发起调用。没有降级或更改项目 Jackson 版本。

官方创建工具会生成签名链接并调用预创建，但不向上层暴露预创建的业务结果；因此不能仅凭生成链接认定交易或支付成功，实际交易存在性和支付结果始终以服务端查单为准。

## 使用与人工验收结论

入口：`http://127.0.0.1:18085/#/assistant/index?pilot=mcp`。选择已有课程会话，点击课程卡片“沙箱购买”，确认金额后生成链接，使用支付宝沙箱控制台的买家账户付款，再回到弹窗查询。

支付成功场景的判定条件为服务端查到 `TRADE_SUCCESS` 或 `TRADE_FINISHED` 且金额匹配。用户已反馈实测验收成功，本轮沙箱购买与查单范围可以收尾；该结论来源于用户人工验收反馈，本轮记录更新未重新调用支付宝接口。

启动/检查/停止说明：[scripts/mcp-alipay/README.md](../../scripts/mcp-alipay/README.md)。日常 8088/8087 服务未由本任务部署或启动，未提交、推送代码。

脱敏证据保存在忽略目录 `target/mcp-alipay/`：浏览器检查日志、`checkout-browser.png`、`cashier-browser.png`、订单前后记录、`boundary-checks.json`、`check.json`。`verified.json` 保留人工验收前的自动联调快照，后续用户反馈另记于 `user-acceptance.json`。构建及测试日志位于 `target/alipay-sandbox-preflight/`。这些路径不保存应用私钥或支付宝公钥。
