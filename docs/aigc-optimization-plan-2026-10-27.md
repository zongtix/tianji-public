# 智能客服后续优化执行计划

日期：2026-10-27。最新状态：本次确认的有限澄清与课程正文/卡片事实约束已完成[本地交付](aigc-delivery-2026-10-27.md)，201项Java检查、43项Python检查、最终原七轮程序门禁及来源初审通过；独立人工验收及部署待完成。早期[七轮真实批次](aigc-seven-turn-acceptance-2026-10-27.md)的失败记录保留，不因新版本交付改写。各阶段见[执行记录](aigc-optimization-execution-2026-10-27.md)。以下保留原计划和后续范围，不宣称全部优化建议都已实施。

## 1. 目标与范围

优先保证课程导购回答可信、异常行为可解释，并能通过固定案例判断改动是否有效。执行顺序为：核实当前基线 → 修正文档和建立评测门禁 → 修复已复现的问题 → 有依据地补强异常处理 → 最终验收。

本计划以 Hermes 的 [优化清单](aigc-optimization-backlog-2026-10-26.md) 为输入，结合当前源码和后续验收记录重新排序；原清单中的代码片段、优先级和面试话术不直接视为实施要求。

用户随后要求“按此计划执行”，本地实施已获授权。重启日常服务、部署、配置切换及新增付费批次仍按本计划的范围和预算约束处理；本轮未执行这些动作。

实施范围以 `tj-aigc` 的文档、现有评测工具及必要的局部修复为主。保留现有 Agent、课程工具白名单、资料投影、确定性事实回答、MCP 来源边界、RAG、SSE、记忆和 Redis 协调机制。保留工作区中全部既有改动。

## 3. 阶段一：固定基线和修正文档（约半天）

### 3.1 固定当前事实

- 记录分支/提交、相关工作区差异和文件哈希；有必要运行本地服务时再核对实际 JAR、进程启动时间、配置与提示词来源。
- 整理已有案例和证据，按“通过且保留回归 / 旧失败待复现 / 未覆盖”分类。10 月 25 日的旧失败不能直接当作当前仍失败。
- 优先复核工具标记泄漏、未问内容主动展开、指代丢失、前置条件被弱化等用户可见问题。先重放已保存快照和本地受控路径；依赖真实模型的问题标记为待真实复验。

### 3.2 校正 README

修改 `tj-aigc/README.md`，按源码重新核对能力、接口事件、记忆、取消与并发说明；链接现有课程、知识库、音频、MCP 和观测文档。

说明 Redis 租约提供的跨实例协调机制及其边界，不据此宣称已完成多实例容量、故障切换或会话恢复验收。面试话术只描述当前实现和已验证范围，待实现项明确写为后续工作。

**验收：** 文档每项能力都能对应代码或限定验收记录；不再保留相互矛盾的旧描述。输出当前问题表及可复用基线，不发起新模型调用。

## 4. 阶段二：补齐路由/工具评测与本地门禁（约 1–1.5 天）

### 4.1 复用评测入口，独立管理课程案例

保留 `docs/rag-evaluation/cases.json` 的积分案例及历史结果，不强行把课程工具问题混入 RAG 必要片段指标。复用 `scripts/local/verify-agent-workflow.py`、`verify-chat-performance.py`、现有 MCP 案例和评分发布工具；只补采集、断言和汇总缺口。

课程案例首版控制在 20–30 条，先对现有案例去重。覆盖浏览、个性化推荐、指定课程咨询、两课比较、价格/有效期、多轮指代、澄清、空结果、字段缺失、检索失败、取消和资料投影边界。使用合成历史与受控业务快照；真实服务案例执行时重新读取事实。

案例分为可用于调整的集合和固定保留集合；每份案例说明来源、预期业务结果与判定理由。先完成离线校验，新增真实模型评测另列批次、资料范围和调用预算。

### 4.2 明确评分口径

| 指标 | 判定方式与边界 |
| --- | --- |
| 路由命中 | 对有明确金标的案例精确匹配；澄清单独表示，不混同 KNOWLEDGE。确有多条合法路径时预先列明并报告歧义，不能看到结果后放宽 |
| 工具约束满足 | 校验必要读取、课程 ID/参数、核实与推荐的先后依赖、禁止工具及取消后无后续调用；允许预先定义的等价查询路径 |
| 协议与安全不变量 | SSE 终止次数、越权、错误脱敏、资料授权范围、卡片/历史一致性等程序断言 |
| 内容符合需求 | 对照原问题和业务依据复核条件、程度、遗漏、无依据结论和未问内容；关键词仅作辅助告警 |
| 检索质量 | 沿用有明确标注的 RAG 指标；无答案、澄清和不可适用项使用各自分母 |

程序能确定的结果用程序断言；内容语义判断保留来源初审与人工复核状态。缺日志、未执行、未复核和 not_applicable 都不算通过。

工具指标建议命名为 `tool_contract_pass_rate`，避免固定序列前缀错判合法路径。若保留原建议的 `tool_seq_match`，只用于确实要求固定顺序的案例，不替代业务约束评分。

### 4.3 增加可重复的本地比较

优先新增一个离线比较脚本，读取统一汇总结果；必要时只对现有汇总器增加适配，不重写已有历史报告逻辑。新结果写入新批次目录，保留失败记录。

- 比较前校验数据集/案例 ID、资料哈希、评分版本、有效配置、模型选项和提示词哈希；保留代码版本差异作为待评估改动。比较策略改动时显式列出允许不同的配置项，其他条件必须一致。
- 不可比较、缺少必需结果或未执行项导致退出非零，并解释原因，不能默认为通过。
- 权限、取消、课程事实和协议等确定性关键案例要求全部通过；任何新失败阻断。
- 路由与工具指标先以同案例不低于基线为默认标准，列出逐例得失；阈值在跑候选前固定，不为了放行临时调整。
- 内容复核未完成时，状态为“程序门禁通过，内容待复核”，不能输出整体质量通过。
- 时延和用量先描述变化；只有可比且有足够重复的样本才设性能门槛。用量缺失标记 unavailable，不补零。

**验收：** 已有结果可离线重复汇总；故意制造关键案例失败、指标下跌、样本缺失、版本不兼容时均退出非零；恢复合格输入后程序门禁通过。路由和工具结果能追溯到案例与原始调用。

Langfuse 沿用现有发布/回读脚本；确认有真实可判结果后再新增路由与工具 BOOLEAN 配置。不因本地模拟或配置创建成功就宣称真实评分已完成，亦不把写入 Langfuse 设为离线门禁的前提。

## 5. 阶段三：根据复现结果修复用户可见问题（约 0.5–1.5 天）

只处理阶段一、二确认仍存在的问题；已通过的资料投影与确定性事实回答保留回归，不重新换方案。

| 问题 | 实施原则 | 验收 |
| --- | --- | --- |
| 工具标记泄漏 | 先区分模型正文、工具协议与 SSE 序列化来源，再在拥有该问题的最小边界修复；不先用正则删除正文掩盖问题 | 跨分片、正常工具调用及普通文本均有针对性回归；真实模型复验另记 |
| 多轮条件/课程指代丢失 | 核对实际传入的历史、卡片身份和工具参数；改有证据的缺口 | “第二门”“刚才那个”“按这个再推荐”对应正确课程或必要澄清 |
| 缺失/裁剪/失败混淆 | 复用已有投影标记、事实回答和错误分类 | 有依据正常回答；缺依据不肯定；本轮未展开不说成课程没有 |
| 前置条件弱化、附带未问内容 | 对照当前事实出口与生成出口定位；不扩大确定性回答的适用范围来伪装覆盖 | 保留全部必要前置条件及程度，回答当前问题，不主动追加无关目录/框架说明 |

**验收：** 先有失败复现，再有对应修复；相关回归通过，固定保留集合无新增失败。无法在本地复现的模型问题保留待验证状态，不虚构修复结论。

## 6. 阶段四：异常处理补强，逐项作出决定（约 1–2 天，按需执行）

这部分改变用户可见行为，实施前给出明确的行为表和测试期望；不直接套用 Hermes 的示例代码。每项单独验证，避免把降级、重试、卡片时序一起改掉。

### 6.1 路由失败

推荐先保留专用错误，优化其可理解性，并评估仅对明确瞬时网络/服务错误做一次受限路由重试。解析失败、鉴权失败和用户停止不混入瞬时故障重试。路由重试也受整轮预算和当前请求归属约束。

不自动把课程请求送入无课程工具的 KNOWLEDGE 分支，不承诺“路由模型断开后仍有正常业务答案”。若改为确定性澄清，要明确它表示暂时无法分类，并决定是否写入历史，不能假装用户问题本身含糊。

15 秒改 8 秒不单独当作优化；先看路由耗时和超时分布，再决定是否调整。

### 6.2 工具轮数耗尽

保留八轮硬上限，不为完成清单新增配置项。记录本轮执行摘要，区分无可靠证据、部分可靠证据、资料已充分但循环未结束。

只允许用已验证证据回答其支持的部分，不自动提交推荐、不展示未经可售/价格核实的卡片、不把未执行查询解释为无课程。工具结果不足时明确说明本次未能完成；不能直接调用普通 finalPrompt 就视为降级完成。

### 6.3 回答阶段重试

与路由重试分开评估。若实施，仅包住冻结后的最终回答模型调用；工具准备、推荐提交、记忆保存和标题生成不随之重跑。仅在未发送任何可见内容、请求仍有效且预算允许时尝试一次。

优先用瞬时 5xx、停止、已出文字及已发卡片等受控故障验证，确保不重复工具、不重复消息、不重复卡片、没有取消后的新调用。确定性事实答案不引入模型重试。

### 6.4 卡片与文字失败

优先评估“文字错误时交付已核实卡片”的局部恢复，先写清卡片是否已发送、正文是否部分输出、历史如何保存、错误如何结束四种状态；比较它与提前发卡片的改动面，再选择较小方案。

保留当前停止后不补发未发送卡片的语义。正常、首字前错误、部分文字后错误、主动停止、断连、失去租约均需验证，客户端可见卡片与历史恢复结果一致。

**阶段验收：** 相关故障矩阵全部通过；失败路径不新增无依据正文或推荐。若保留现有契约更合理，记录不改的理由也算该项决策完成，不能把方案未实现写成能力已具备。

## 7. 后置事项与触发条件

| 事项 | 何时再做 |
| --- | --- |
| RAG 语料扩展 | 需要比较检索策略且现有数据确实无法区分时，建立独立评测语料与标注。优先同领域相似干扰、否定、跨文档和无答案问题；不以文档数量当质量指标 |
| 课程文档加入知识库 | 先核对课程索引与授权知识库的区别及导入链路；不能把 CourseDocumentService 的课程入库当作积分知识库扩充 |
| RAG 独立调度器/并发限制 | 观察到排队、线程竞争或受控并发下的资源问题，并能复现；先定位阻塞位置，不凭一个 block() 判定共享池已耗尽 |
| 按 agent 统计成本 | 复用已有模型实际用量，区分 route、prepare、answer、title、rewrite 等阶段与整轮业务 agent；完整性核实后再汇总。agent 用低基数属性，Token 是数值；缺少价格表或完整用量时只报告 Token，不能直接当金额成本 |
| 摘要记忆 | 有真实长会话上下文丢失或预算问题，且具备摘要事实保真评测时再设计 |
| 更换路由模型/合并路由与工具 | 现有链路质量稳定、调用归因明确后作为独立实验；本计划不改变架构 |

## 8. 最终验收与交付

### 本地与受控验证

按实际修改选择 `AgentWorkflowTest`、`CourseToolPreparationTest`、`CourseToolsTest`、`CourseFactAnswerTest`、`CourseCardStreamingTest`、`ChatStopMemoryTest`、`ChatRedisCoordinationTest`、`ChatObservabilityTest` 及必要 MCP/RAG 回归。新建测试只保护本次有实质风险的行为，不重复现有断言。

评测脚本用离线夹具验证门禁、分母、版本比较与缺失处理。相关检查通过后不为了凑数量无限扩大测试；有新改动或未解决风险才补跑。

### 真实服务与内容复核

本地阶段不调用模型。后续真实验收先列明问题、课程/文档范围、目的地、隔离实例与新调用预算，核对是否已有适用授权；历史额度不能默认重复使用。

范围允许时重跑原七轮导购流程，并补充本次改变的失败路径。没有实测某条链路就保留未覆盖；两门课的限定试验不能代表全课程推荐。资料范围必须在搜索、浏览、详情和发往模型的最终请求处共同约束，不能只限制 MCP 单详情。

同时核对 SSE、正文、卡片、历史、实际工具和有效提示词；真实模型结果由来源初审与独立人工复核分开记录。专用测试会话按已授权范围清理，不触碰用户原会话、课程数据或日常配置。

### 交付标准

1. 更新后的 README、当前问题/决策表与逐项实现差异。
2. 固定案例、可复用基线、逐例比较报告和一条本地门禁命令。
3. 每项改动的复现、测试与必要真实证据；失败及未覆盖项保留。
4. 明确区分“代码实现完成 / 本地验证通过 / 限定真实验收通过 / 独立人工复核完成 / 日常环境启用”。
5. 仅回退本轮局部改动即可恢复原行为；不需要修改课程、重建索引或切换架构。

前两阶段预计 1.5–2 天；后续修复与异常补强视复现结果约 1.5–3.5 天。真实调用、人工复核和环境等待单独计，不承诺在固定工时内全部通过。先交付可比较的基线和门禁，再逐项决定哪些异常策略值得改。
