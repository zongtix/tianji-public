# 课程讲义 RAG 方案与分工

状态：方案已冻结并完成 P4 文档收口；**2026-10-31 产品拍板日常开启**（`TJ_AI_COURSE_MATERIALS_ENABLED` 默认 true，回退设 false）。实现任务见 [2026-10-31-course-material-rag-implementation.md](./2026-10-31-course-material-rag-implementation.md)。演示/回退见文末附录。

Cursor 验收清单与 AI 保留题草稿：`docs/rag-evaluation/course-materials/`。

## 1. 要解决的问题

用户已经知道课程或正在学习某门课程，希望问“讲义如何解释缓存击穿”“这段示例为什么使用互斥锁”，并获得能追溯到课程原文的回答。课程价格、有效期、状态与介绍继续查询现有业务接口；讲义检索返回回答所需的具体片段。

首期目标是跑通一门课程的“定位课程 → 校验资料范围 → 检索讲义 → 引用原文回答”。不增加新的 Agent，不建设上传后台、OCR、视频转写、笔记共享或全平台知识搜索。

与 DeepSeek 讨论后的取舍：先做公开演示资料，付费能力留到身份、权益与内容外发边界均有验证后接入；讲义独立存储，复用检索组件。首期采用工具调用以兼容现有咨询流程，不预设它一定比服务端预检索更快；若工具选择回合成为主要耗时，再对相同资料和授权做小样本预检索对照。

Cursor 已通过可用的 Cursor Auto 提供方完成独立只读审阅。采纳其三项收敛建议：补齐可执行的路由/快捷回答验收；将试点能力验证与算法对照分成前后两道闸；由第三方负责测试设计和标签审阅，减少资料作者同时定义问题与评判答案的偏差。架构继续沿用本方案，不新增一套实现。

## 3. 推荐的首期范围

使用明确标注的公开演示资料：一门 Redis 主题主课，另有一门 MySQL 主题对照课用于跨课程隔离测试。优先复用已有演示课程；实施时先只读确认课程名称、ID 和目录，确有缺失才设计单独的演示数据增量。

DeepSeek 准备主课 3～5 篇短讲义/FAQ、对照课 1～2 篇相近词资料；Codex 对技术事实、课程绑定和资料声明复核。资料注明原创或合法来源、演示用途、核验日期，不冒充现有真实售卖课程的官方讲义。真实课程有可靠来源后再替换试点数据。

首期源文件使用受控 Markdown 加服务端 manifest，便于阅读、版本管理和复现，不将长讲义塞进 `course_content.course_detail`，不立即新增资料管理业务表。manifest 指明 `courseId`、`materialId`、标题、来源、发布状态和公开演示属性。源文件不会作为静态网页目录直接公开。

平台学员问答不自动转换为官方 FAQ；其中的用户身份、隐藏内容、匿名内容和未经审核的答复须另行处理。首期只使用专门准备并核对的演示讲义。

首期仅支持登录用户读取服务端发布的公开演示资料；任何受限资料默认拒绝。正式售课推荐对演示课程的过滤保持不变，演示通过独立测试实例/受控课程上下文验证，不去掉生产过滤规则。

启用试点时，服务端可将已核验的公开试点课程名称与 ID 放入本轮定位上下文，使用户能按名称提问；它不代表用户获得其他课程权限，也不修改正式推荐候选池。明确指向某门课的讲义问题路由到 CONSULT，通用技术常识问题继续沿用原知识解释路径。首期不依赖新增前端入口或用户手抄 ID。

## 4. 请求链路与接口约定

1. 用户通过自然课程名、已有课程上下文或历史卡片定位课程；歧义时澄清，不要求用户输入内部 ID。
2. CONSULT 可调用新增的 `searchCourseMaterials(courseId, question)`。`courseId` 是待核验的定位参数，不是授权证明；用户 ID、发布版本、访问级别和 ES filter 均不开放给模型设置。
3. 服务端从请求入口传入的可信上下文取得用户身份、当前请求有效性和生成归属；检查课程与资料发布范围，计算唯一检索范围。
4. 在 ES 查询内限制 `courseId`、当前已发布的 material/version；不能先全库取回再过滤。检索前后、返回工具结果前检查取消与归属；受限材料没有通过授权就不取回、不传给模型。
5. 工具只返回片段及证据身份，不在内部再调用一次回答模型。复用现有准备阶段和最终流式回答阶段，避免重复生成和工具中间文本进入可见流。
6. 模型根据原问题和工具返回证据回答，按“课程／讲义标题／章节／引用编号”标注来源；业务工具仍负责实时价格和有效期。

每轮由服务端限制资料检索次数，初始最多两次；每次最多返回三个完整片段，并检查最终请求预算。预算放不下时舍弃完整片段或明确报错，不按固定字符数截断关键条件。调用次数、topK 和范围不交给模型自行设置。

身份落点明确在 `ChatServiceImpl` 完成会话归属检查并构造 `AgentContext` 时：显式传递服务端确认的 userId，再放入只读工具上下文。不得从模型参数或 conversationId 字符串解析身份，也不得依赖工具执行线程的 ThreadLocal。首期检查实际日志和 trace 的采集范围，只使用公开演示资料及合成问题，不主动新增正文埋点；真实用户和付费接入前再验证内容采集的停用或脱敏。

拟定工具返回结构：`status`、`courseId`、`courseName`、`materialVersion`、`evidence[]`。证据包含 `materialId`、`chapterTitle`、`chunkIndex`、`contentHash`、`excerpt`、`citationId`。对模型可见的长 ID 使用字符串；引用不暴露内部文件路径、对象存储私有 URL 或其他课程正文。

状态明确区分 `OK`、`EMPTY`、`ACCESS_DENIED`、`TEMPORARILY_UNAVAILABLE`。授权或检索异常不能当成空结果，更不能回退为无范围全库查询。对于明确要求课程讲义依据的问题，空结果和拒绝访问由服务端保留确定性边界，不能仅靠提示词让模型自行决定是否补写答案。

首期以单课程内容问答为主；混合价格和讲义的问题需要分别依据对应工具，检查现有 `CourseFactAnswer` 快捷回答不会提前吞掉讲义子问题。没有检索证据时，可以说明资料不足，不以常识代替该课原文。

## 5. 索引与复用边界

新资料使用独立的课程讲义索引，建议名称 `tj_aigc_course_materials_v1_1024`；验证使用 `tj_aigc_eval_materials_<batch>`。不合并原课程候选索引、积分规则索引或优惠券评测索引。

复用既有 Embedding 配置、Markdown 切分规则以及 `KnowledgeRetrievalPipeline` 的向量/BM25/RRF/重排能力；不嵌套调用会组装聊天请求的 `KnowledgeRetrievalAdvisor`。以独立的 `CourseMaterialSearch` 类型暴露查询能力，避免新建全局 `VectorStore` Bean 改变原知识库注入目标。

片段最低元数据：`courseId`、`materialId`、`sourceId`、`title`、`headingPath`、`contentHash`、`chunkIndex`、`embeddingModel`。只有经过核验的数据库章节才填写 `catalogueId`，Markdown 小标题不伪造成正式小节 ID。访问属性和发布版本以服务端 manifest 为准，ES 元数据不能单独决定权限。

首期显式导入冻结版本：同内容稳定 ID、重复导入跳过；不同版本拒绝直接覆盖，验证新版本使用新隔离索引。默认不做自动扫描、MQ 同步或后台重建。配置开关默认关闭，关闭时不注册讲义工具、不创建索引。

## 6. 付费资料是第二阶段

正式付费讲义接入前必须落实：

- 权威学习服务验证当前用户和课程的有效学习资格；调用身份由服务端绑定，不接受模型参数中的 userId。
- 用增量接口或专用客户端区分 ALLOWED、DENIED、UNAVAILABLE，保持已有 Feign 方法的兼容性，不把全局 fallback 改动夹带进首期。
- 切线程后的身份传递、两用户并发隔离和课程归属有测试证据；资料发送给模型前完成授权，并考虑授权失效后的输出和历史访问。
- 课表资格不代表可以任意传播教材；资料来源和模型外发范围也要确认。
- 免费课程不自动代表全部讲义公开，视频 `trailer` 也不等于讲义试看权限；文档须有明确访问策略。已购课程的学习权以学习服务为准，不直接用“仍在售／仍处于购买期”代替学习资格。
- 付费正文放在私有资料存储，不提交到公共仓库。当前观测可采集模型消息及工具结果，因此付费试点前须核对日志、Langfuse 和聊天历史的内容处理，验证停用或脱敏实际生效，不能只隐藏最终页面。

第二阶段验收前，不把公开试点描述为“已支持付费课程讲义”。

## 8. 评测设计与验收

**闸 A：先证明新增资料工具可用。** 先用一组小核心场景验证真实路由与工具执行：明确课程名的讲义问题进入 CONSULT，通用技术解释仍走原知识分支；“讲多深”等问法和价格＋讲义混合问题不能被 `CourseFactAnswer` 提前吞答；绑定积分库的会话仍不能调用课程工具。联动检查 `route-system-message.txt`、`consult-system-message.txt`、`course-tool-preparation.txt` 以及最终快捷回答条件，而不只增加工具白名单。完成“现有工具 vs 新增讲义工具”的能力基线和可核实引用后，再开启算法比较。

**闸 B：再比较检索策略。** 准备约 24～32 个冻结问题，覆盖直接讲义问答、同义表达、条件/否定、跨章节依据、相似课程干扰、资料缺失、价格/讲义混合问题。另用确定性技术测试验证未登录、非试点课程、付费资料拒绝、服务异常、停止、并发用户隔离，以及讲义中含“忽略权限”等指令时不能改变检索范围。题目来源、标注作者、集合用途和冻结时间分别记录；不能用原积分＋优惠券成绩作为新讲义效果背书。

两类比较分开：

1. **现有工具基线**：只查课程介绍和目录，衡量新增讲义后能回答哪些原来资料不足的问题。它与讲义 RAG 的资料范围不同，不能把差异直接归因于某种检索算法。
2. **同讲义语料算法对照**：A 原向量、A′ 扩大向量、B 混合、C 重排；使用同一冻结资料、问题、标签、授权、模型和提示词。比较候选证据召回、最终上下文覆盖、排序、答案依据、引用、拒答、耗时和可获得的用量。

不预设漂亮的召回率或 p95 作为结果。授权边界在固定安全测试中必须全部满足；每条回答判断应附可核对的证据或具体问题，资料不支持的断言列为缺口。候选深度不同不称为相同 K 的 Recall@K，证据覆盖不称为答案准确率。

AI 构造题与 AI 来源审阅都如实标注；留出用户自然提问和独立人工复核的位置，不能称已有真实用户流量或独立人工泛化集。失败不靠修改标签或重复运行至通过来掩盖。真实模型评测完成后再决定模式，不因已经实现 C 就宣布 C 最佳。

## 9. 发布与回退

首期曾默认关闭；验证与辅助验收通过后，**2026-10-31 产品拍板日常开启**（`application.yml`：`tj.ai.course-materials.enabled: ${TJ_AI_COURSE_MATERIALS_ENABLED:true}`）。回退：环境变量或配置设为 `false`，并可撤销试点 `publishStatus`。已有课程卡片、课程语义推荐、积分库授权及停止协议必须保持兼容。

回退先关闭讲义开关并撤销本试点发布范围；隔离索引和归档结果保留用于核查。不做数据库整库恢复，不删除旧课程或旧索引。付费接入、上传后台和全平台资料管理另行规划。

### A. 本地 / 验证实例开启试点（最小步骤）
