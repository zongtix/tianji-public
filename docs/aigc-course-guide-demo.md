## 演示流程

以下为人工演示脚本，本轮没有再次发送这些聊天问题。实际发送会使用现有真实模型配置。

| 步骤 | 在页面中的操作 | 应关注的结果 |
| --- | --- | --- |
| 1. 目标推荐 | 新会话发送“我有Java后端基础，想补HTML、CSS和JavaScript，有什么合适课程？请说明依据并展示卡片。” | 用适用人群、介绍或正式目录解释推荐理由；卡片展示当前名称、价格、有效期；不凭课程名称保证学习效果 |
| 2. 继续追问 | 同一会话发送“这门课能确认教React吗？” | 识别“这门课”，重新核实详情；区分介绍声明和正式目录，无法确认的部分不说成已核实 |
| 3. 基础核对 | 独立新会话说明“只学完Java基础，还没用过Spring Boot和MyBatis”，询问微服务课是否适合现在学 | 保留用户已知基础，指出课程明确列出的框架前置要求尚未满足；不承诺课程会补齐这些基础 |
| 4. 两门比较 | 独立新会话说明“有Java后端经验，熟练使用Spring Boot和MyBatis，现在最想补前端”，比较《Java程序员的前端课程》和《可能是史上最全的微服务技术栈课程》 | 围绕当前补前端目标给出选择，说明两门主题和基础要求的关键差异；当前回答冗余问题仍保留 |
| 5. 详情与恢复 | 点击卡片，在新标签页查看课程介绍和目录；返回助手后刷新并打开自己的历史会话 | 路由和课程一致，新标签页能续登；历史保留原问题、最终答案和对应卡片；图片失败不会无限阻塞页面 |

当前资料的核对样本为两门正式课程：前端课覆盖HTML/CSS/JavaScript的对应目录，微服务课明确要求Java开发基础及熟练使用Spring Boot、MyBatis。介绍和有限目录不足以证明教学深度、完整覆盖、就业或学习收益，不能将两门样本的验证推广为全量课程准确率。
