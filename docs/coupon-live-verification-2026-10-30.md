# 优惠券异步功能开发环境验收记录

## 结论与范围

2026-10-30 完成真实 MySQL 与 RabbitMQ 下的异步领取、兑换、重复消息、事务回滚及故障恢复验收。
14 项业务/基础设施检查通过，另完成原数据保护和测试数据清理两项检查。
这是开发环境后端闭环验收，不是生产发布、前端联调、网关真实登录或性能压测。
本阶段没有修改业务 Java 源码，没有提交、推送或修改公共 Nacos 配置。

## 实际运行环境

- 使用原开发环境 SSH 隧道：MySQL 3306、RabbitMQ 5672、管理 API 15672、Nacos 8848。
- 数据库 `tj_promotion`，MySQL 8.0.27，InnoDB，隔离级别 `REPEATABLE-READ`。
- RabbitMQ vhost `/tjxt`，真实声明 `promotion.coupon.claim.exchange` 和 `promotion.coupon.claim.queue`，观察到两个消费者。
- Nacos namespace `tianji-local-boot3`，复用既有配置且不保存或输出凭据。
- 最新 `tj-promotion.jar` 使用 Java 17 离线 package 构建成功；本次打包跳过测试，既有 Surefire 报告合计 168 项、0 失败/错误/跳过，并非本轮重新执行。
- 专用实例只监听 `127.0.0.1:18092`，禁用服务发现注册；`tj.promotion.async.enabled=true` 仅以该进程启动参数设置。
- AMQP 经本任务自有 `127.0.0.1:25673` TCP 代理连接共享 broker，仅停止代理注入断连，不停止共享 RabbitMQ。
- 验收启动器加载实际 `PromotionApplication` 和打包代码，但移除 `couponIssueTask`、`xxlJobExecutor`，避免既有定时任务修改无关数据或注册任务执行器。
- 连接池会话设置 `innodb_lock_wait_timeout=2`，仅作用于验收实例，不改变数据库全局配置。

HTTP 直连内部服务，使用两个专用测试用户 ID 和可信内部 `user-info` 身份头，不是网关签发的真实登录态。
未新建或更改真实用户账号，不应据此宣称外部用户可以绕过登录。

## 验收结果

| 检查 | 实际结果 |
| --- | --- |
| 真实消息拓扑 | 队列存在，两个消费者就绪 |
| 身份和幂等头 | 无身份返回 401；缺少幂等头返回 400 |
| 公开领券闭环 | HTTP 返回 PENDING，随后 SUCCEEDED，用户券落库 |
| 幂等和用户隔离 | 同键同参数返回原结果；改参数 400；其他用户查询 400 |
| 真实重复投递 | 通过 RabbitMQ 管理 API 重发成功请求，仅保留一张用户券；测试券限领 10，避免限领掩盖重复发券 |
| 同用户并发限领 | 两个不同请求键争限领 1 的券，一成功一失败，只发一张 |
| 多用户最后库存 | 两个用户争库存 1，一成功一失败，只发一张 |
| 兑换码单次使用 | 同码先后由两个用户兑换，首次成功、第二次失败，码 USED、仅发一张 |
| 兑换事务回滚 | 专用券有效期配置不可用，核销后发券失败，码回滚为 UNUSED/user_id=0；修复该测试券后新请求成功 |
| 发放窗口结束 | 最终 FAILED，没有生成用户券 |
| 领取真实锁超时 | 持有专用 coupon 行锁，工作事务超时；PENDING、attempts=1、两调度时间同步推进 2 秒；释放后成功且只发一张 |
| 兑换真实锁超时 | 同样观察一次退避，等待期间码仍 UNUSED；释放锁后成功，仅一次核销和发券 |
| AMQP 断连恢复 | 关闭自有代理，HTTP 仍受理且数据库 PENDING/attempts=0、未发券；恢复代理后自动成功 |
| 服务重启恢复 | 在代理断开时受理 PENDING，停止专用服务；恢复代理并重启服务，原 requestId 自动成功；旧成功请求重放不再发券 |

## 数据保护与收尾

使用批次归属清单创建 10 张专用券、3 个专用兑换码，并产生 14 条请求、9 张用户券。
清理前确认全部请求已终态、队列 ready/unacknowledged 均为 0，并以原始快照确认其他数据未变。
停止本任务服务和代理后，校验券名批次、用户归属、请求参数及码关联，在单事务内删除上述专用数据。
没有删除未完成请求、重置 AUTO_INCREMENT、清空共享队列或修改原业务数据。

清理后全表行数及 SHA-256 与迁移前快照一致：

| --- | --- | --- |
| coupon | 9 / 9 | 一致 |
| coupon_scope | 11 / 11 | 一致 |
| user_coupon | 6 / 6 | 一致 |
| exchange_code | 1000 / 1000 | 一致 |

新增请求表保留，最终 0 行；新增 MQ 交换机、队列和绑定保留作为功能基础设施，未执行 purge。
专用 18092 实例与 25673 代理已停止，常规 8092 服务没有启动或切换；源代码异步功能仍默认关闭。
