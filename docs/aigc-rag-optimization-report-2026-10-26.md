# 天机学堂知识库 RAG 优化收口报告

报告日期：2026-10-26（Asia/Shanghai）。项目：`D:\Java\tianji`，分支：`feature-aigc`。

## 1. 最终结论

**本轮RAG优化结束，最终保留本地C模式＋knowledge-v1。** 已落地向量与BM25混合检索、应用层RRF融合、qwen3-rerank专用重排、上下文预算保护、观测及固定评测。真实对照证明混合检索能够补回原向量路径漏掉的积分规则，重排能够把关键依据排进最终上下文。

当前C＋v1完成32题真实验收，核心结论来源初审32/32通过，仍有4题表达警告。v2—v5均不作为默认回答模板。额外上下文筛选策略未默认启用，完整D模式实验未执行。

收口表示本阶段配置和交付范围冻结，不表示所有表达问题、全部业务场景或长期稳定性已经验证。遗留表达问题按非阻塞项记录，本轮不再追加调参、模板或模型评测，也不把资料扩展列为继续本轮优化的前提。

## 2. 目标与原有问题

原知识库主要采用向量检索，默认topK=3、相似度阈值0.6，召回片段直接用于回答。在既有积分资料中出现过：

- 术语或特定业务表达无法召回，例如两张积分消息/明细表的区别。
- 召回候选包含关键资料，但最终前三片段没有选中，导致已有明确规则的问题仍无法回答。
- 回答模型重复确认用户已给出的条件，或追加未问的规则、资料缺口与假设。
- 缺少统一阶段追踪及固定对照依据，难以解释质量与额外延迟的关系。

本轮保留Spring AI 1.1.2和现有技术栈，不改变课程业务事实的核验方式。知识库RAG与课程语义检索是不同链路，本报告的积分问答结果不能解释为课程导购准确率。

## 3. 已落地的链路与边界

```text
服务端身份、会话归属及知识库授权检查
  → 固定授权文档范围
  → 查询改写：KEEP / REWRITE / CLARIFY
  → 向量检索＋BM25检索（各自使用授权过滤）
  → RRF融合、稳定身份去重并保留跨路排名贡献
  → qwen3-rerank重排
  → 选择最多3个完整片段、检查最终请求预算
  → 围绕用户原问题依据资料回答
  → 沿用现有SSE、取消及记忆处理
```

| 能力 | 实现与最终采用情况 |
| --- | --- |
| 查询改写 | 保留既有KEEP/REWRITE/CLARIFY；无历史时不增加改写模型调用；改写文本用于检索，最终回答使用原问题 |
| 混合检索 | 向量参数仍3/0.6；BM25候选上限10；两路在检索阶段过滤授权范围 |
| RRF融合 | 应用层实现，rankConstant=60，融合上限12；同一路去重、跨路贡献累加，不依赖ES原生RRF许可 |
| 专用重排 | qwen3-rerank，最多输入12个候选、输出上限6；结果序号映射回原证据，不采用返回文本替换来源 |
| 最终上下文 | C模式最多3个完整片段；额外完整片段预算筛选策略仅在D/B_CONTEXT显式模式使用 |
| 预算保护 | 估算窗口16384 Token、输出预留2048、安全余量512；必要输入超限明确报错，不静默删除历史或截断用户条件 |
| 故障与取消 | 单路故障、两路失败、空结果分开处理；普通重排故障可回退授权融合候选，取消/权限/归属失效应终止 |
| 超时 | 检索准备预算25秒，专用重排超时5秒；不是SSE全流程超时 |
| 观测 | Spring AI/Micrometer/OTel与Langfuse接通，记录阶段、模型、排名、降级、最终状态及可获得的用量 |

上下文Token使用近似估算，不能替代供应商计费。工程保护有针对性测试支持，不因此声称所有真实失败、取消与权限组合都已通过外部模型验收。

## 4. 资料与评测口径

评测使用已核实的《天机学堂积分与签到规则》，索引`tj_aigc_knowledge_v4_1024`共7个片段，embedding为text-embedding-v4/1024维。已记录的实际ES为8.19.23、Basic许可。没有为本轮更换Mapping、安装分词插件、重建或覆盖业务索引。

固定集共32题，其中29题有片段标注，另有2题无答案和1题澄清。前8题为既有调参样例、后24题为既有验证样例；同源小样本不能代表独立泛化集。案例根据规则编写，不是线上真实用户对话。

“片段覆盖率”是最终上下文对标注片段的覆盖；“核心结论来源初审”是Codex逐题对照实际选片后的判断。二者都不是独立人工验收或生产准确率。现有片段标签也不总是最小充分证据集合，不能只按片段数判断回答是否得到支持。

## 5. 真实实验结果

### 5.1 原始检索与混合检索：同批32题

| 模式 | 平均标注片段覆盖率（29题） | 全部标注片段命中 | 来源初审主要缺口 | Advisor总耗时中位数 |
| --- | ---: | ---: | ---: | ---: |
| A：原向量3/0.6 | 83.33% | 23/29 | 6题 | 2157ms |
| A′：仅向量6/0.45 | 100.00% | 29/29 | 1题 | 2709ms |
| B：冻结A参数＋BM25/RRF | 98.85% | 28/29 | 1题 | 2388ms |
| B_CONTEXT：B＋上下文处理 | 98.85% | 28/29 | 1题 | 2422ms |

混合检索找回了笔记18分后补2分、points_message/points_record区别、确认超时/NACK等原向量路径遗漏的资料。A′扩大召回也有收益，但平均资料Token估算由约620增到1512，且没有解决全部回答条件理解问题。B_CONTEXT与B选片逐题相同，这份短资料未测得额外上下文处理收益。

这些数字来自早期同批实验。早期运行器未显式冻结thinking及完整Prompt/返回模型清单，用量采集也不完整；后续已补齐字段，不能追溯宣称早期数据具有同等记录完整性。

### 5.2 重排增量：同条件6题B/C对照

| 指标 | B：混合检索 | C：混合检索＋重排 |
| --- | ---: | ---: |
| 核心结论来源初审通过 | 5/6 | 6/6 |
| 首个标注证据MRR | 0.90 | 1.00 |
| Advisor总耗时中位数 | 1993ms | 2562.5ms |
| 实际专用重排成功 | 0 | 6/6 |

关键案例是“学习已满50分，还能获得签到和问答积分吗”。B遗漏最终上下文之外的章节2；C将该片段从融合第4升到重排第1，使回答能够引用“按积分类型分别计算上限”的明确依据。该题两组原候选与融合分数一致，排序变化有可核对的重排证据。

本批重排平均319ms，总耗时中位数增加569.5ms；端到端差异还含生成与检索波动，不能全部归因于重排。

## 6. 观测、工程验证与数据保护

Langfuse已有可查询的真实成功链路，包含改写、向量、关键词、融合、重排、上下文和生成，重排状态为success且请求正常结束；整轮聊天会话关联、首字/回答完成/整轮耗时及原生Scores也已有独立记录。后续离线评测进程仅用本地注册器收集阶段耗时和用量，没有把本报告全部案例自动写入Langfuse评分。

最近一次候选相关验证为7个Java测试类共64项通过，0失败、0错误、0跳过，覆盖提示词资源、最终预算、检索、重排、改写、知识库路由和准备生命周期。历史更广回归记录为206项实际执行通过、18项跳过；跳过项主要依赖专用临时Redis实例等前提，未计作通过。不同批次的测试不简单相加作为一个总通过数。

真实32题及后续模板实验前后，已核对既有7个片段的完整source哈希、序列号、主分片代际和Mapping哈希一致。评测直接调用生产Advisor，每例隔离固定历史，不创建业务会话或写入聊天记忆，不改课程资料和业务索引。技术故障、取消、权限等测试与真实模型质量验收分别记录。

生成和embedding已有供应商实际返回用量；现有重排组件未采集完整rerank用量，因此不提供全链路费用结论。本报告整理未重新运行测试、重启服务或追加模型调用。

| 项目 | 收口值／状态 |

回退到混合检索B时，将`mode`设为`B`并关闭rerank；回退到原向量路径时设为`A`。配置需按现有启动机制加载，不能假定改磁盘文件就即时切换已创建的Advisor。仅关闭重排但仍保留C标签，会触发回退语义，不能当成正常C验收。

需要停止外部观测时可关闭`observation.langfuse.enabled`。本轮没有修改业务索引内容或Mapping，无需做业务数据恢复。已启用链路的既有提交保留，本次新增候选代码、评测工具及报告依用户授权分批本地提交；无关音频计划文档不纳入提交。各实验清单保留运行时的代码指纹，不因后续提交改写历史证据。

非阻塞遗留包括回答冗余、已知条件理解偶有波动、独立人工复核、未验证的其他资料泛化、完整D模式及完整重排用量。这些是证据边界，不是本轮继续追加工作的清单。本报告不宣称已完成全面生产验收，也不继续引入父子召回、GraphRAG、新Agent或资料扩展。
