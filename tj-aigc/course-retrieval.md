# 课程内容向量入库

2026-10-23 新增：正式章节标题同时进入索引正文和本轮工具详情，目录变更参与版本计算；旧向量更新方式和验收边界见 [目录检索与回答](../docs/aigc-course-outline.md)。

数据准备链路：MySQL 正式课程内容 → 当前配置的 Embedding 接口 → 独立 ES 课程索引。推荐链路现已接入学习目标检索、课程服务复核及既有课程卡片协议。

## 数据与索引

`CourseDocumentService.findCourse()` 按明确的课程 ID，从 `tj_course.course` 与 `course_content` 读取正式数据。课程名称、介绍、适用人群和详情组成一份检索文档，详情中的 HTML 转为纯文本；当前正文列的长度适合一门课一份文档。

- 文档元数据包含字符串 `courseId`、`documentId`、来源、内容哈希、向量模型和维度。
- 价格、销售状态、购买时间没有作为索引中的业务快照，推荐前仍须查询最新业务数据。
- 仅导入未删除、已上架或已完结、且处于购买期内的课程；未到售卖时间、已下架或购买期结束时跳过。
- 同一正文、模型和维度产生稳定 UUID；完整写入后重复导入跳过 Embedding。写入失败后用相同 ID 重试，不新增副本。
- 已有不同正文或模型版本时拒绝覆盖，更新和删除同步留给后续实现，不会自动清空索引。

固定索引：`tj_aigc_courses_v4_1024`，只允许 `text-embedding-v4`、1024 维和 cosine。创建与校验复用现有 `KnowledgeStoreConfig`，运行在独立导入上下文中。课程索引与已有 `tj_aigc_knowledge_v4_1024`、课程关键词索引 `course` 分离。

## 执行

先构建最新 JAR，沿用项目现有 Maven 配置和 JDK 17。

```powershell
$env:JAVA_HOME = 'D:/Java/jdk-17'
$env:Path = "$env:JAVA_HOME/bin;$env:Path"
mvn -s "$env:USERPROFILE/.m2/settings.xml" -pl tj-aigc -am '-DskipTests' package

# 先导入并发课程，并验证“多个请求同时扣库存”的语义检索
./scripts/local/import-ai-courses.ps1

# 再导入全部 12 门演示课程，执行 6 个检索场景
./scripts/local/import-ai-courses.ps1 -AllDemo
```

导入脚本读取当前 Nacos 的 MySQL、ES、Embedding 配置，缺省项使用模块配置；模型密钥沿用现有环境变量。凭据经标准输入传入 Java，不进入命令参数和报告。该命令会真实调用收费的 Embedding 接口，重复导入检查本身不调用模型，检索问题仍需要向量化。

命令使用只读 JDBC 连接，不修改业务表；不会启动业务 Web 服务、注册 Nacos 或调用 DeepSeek。普通 AIGC 服务启动时不会执行导入。

日志和验收报告位于 Git 忽略的 `target/ai-course-import/`，每次执行单独保存。报告包括导入/跳过结果、重复导入验证、问题、预期课程 ID、实际候选和分数。检索不命中预期时保存失败报告并返回非零退出码。

## 验收边界

检索限制在本次明确选择的课程范围内，最多返回 3 个相似度不低于 0.6 的候选。每个候选再次读取 MySQL，排除后来被删除、下架或到期的课程。错误直接报告，不静默改用关键词搜索或模型编造结果。

购课流程仍属于后续功能，本节仅处理课程查找、推荐和详情追问。

测试：`CourseDocumentServiceTest` 使用 H2 和向量存储替身验证业务边界；真实 MySQL、当前 Embedding 接口和 ES 的结果以实际运行报告为准。

## 推荐工具接入

普通会话路由到 `RecommendAgent` 后，新增 `searchCoursesByGoal(goal)` 工具接收学习目标、基础和实际问题。ES 返回最多 5 个相似度不低于 0.6 的课程 ID；工具通过 `CourseClient.getSimpleInfoList` 复核状态、购买起止时间、价格，再用 `getCourseBaseInfoById` 读取当前介绍。模型看到的是最新业务详情，索引正文只用于查找候选。

`CourseSimpleInfoDTO.purchaseStartTime` 是新增的可选响应字段，源自正式 `Course.purchaseStartTime`，由现有 `getSimpleInfoList` 的对象复制返回；未到开始时间的课程也会被排除。

检索成功只向当前请求的 `CourseRecommendations` 候选池登记结果，不直接展示卡片。模型调用 `recommendCourses` 后再次核实价格与状态，沿用原有 `1004` 卡片事件、回答保存和历史卡片指代机制。候选 ID 不能跨请求使用，取消后不追加卡片。

课程名称和明确关键词继续走 `searchCourses`，没有自动混合两路结果。语义检索或当前课程查询失败时返回 `1005 / COURSE_RETRIEVAL_FAILED`，再发送一次 `1002` 结束事件，不把失败当无结果或静默切换搜索方式。

`ConsultAgent` 仍只提供原来的搜索与详情工具；`KnowledgeAgent` 没有业务工具，绑定知识库的会话不进入课程推荐。原始提问写入历史，工具内的检索文本不会替换用户原话。

### 配置

正常服务在 `tj.ai.knowledge.enabled=true`、`tj.ai.knowledge.store-type=elasticsearch` 且 `tj.ai.course-retrieval.enabled=true` 时提供新工具。模块配置中的课程开关默认开启；可通过 `TJ_AI_COURSE_RETRIEVAL_ENABLED=false` 或对应配置项关闭，重启生效。知识库未启用或使用 Redis 时保持现有关键词工具，不引入新的 ES 课程依赖。

`CourseRetrievalConfig` 内部构造专用课程向量存储，只暴露 `CourseSemanticSearch` Bean，主知识库的 `VectorStore` 注入目标不会改变。课程索引继续校验模型和维度，不修改已有知识库授权、召回参数或资料。

## 课程导购收口

本轮完善“学习需求 → 真实课程 → 适配判断与对比 → 课程详情入口”，不增加智能体、预算筛选或下单支付工具。

- 推荐分支保留完整学习需求进行语义检索；名称搜索只有卡片时，先查询当前详情，再根据目标、适用人群和资料中明确的前置基础解释理由。只推荐合适的候选，缺少关键需求时再追问。
- 已明确课程的对比、推荐后的适配判断与购买入口追问交给咨询分支。历史卡片只用于定位，重新查询双方课程详情；不为比较已有课程而重新推荐其他课程。
- 不把相关知识点夸大成课程未承诺的完整解决方案，不编造答疑、证书、就业保证或购买收益。未知维度应说明资料未提供。
- 推荐回答中的价格和学习有效期以最终推荐工具的结果为准，沿用现有卡片与详情页入口，用户在详情页继续决策。卡片不代表已下单或已获得学习权限。
- `CourseInfo.price` 改为可空 `Double`：缺失或负价格为未知，明确零价格仍为零。独立的 `CourseBaseInfoDTO` 增加可选 `free` 字段，由正式课程的 `free`（1 免费、0 付费）复制转换；免费标记优先于残留价格，避免文字与免费卡片冲突。既有课程详情接口与 `CourseFullInfoDTO` 不变。

复用已有真实模型脚本执行导购场景：

```powershell
python scripts/local/verify-semantic-recommendation.py --real-model --guide --report target/course-guide-live/report.json
```

前提是本机独立测试服务已加载当前 JAR，默认端口仍为 `18086`（课程）和 `18096`（AIGC），并已导入演示课程。脚本向当前配置的模型服务发送合成问题、测试历史与课程工具结果，只创建并清理专用测试身份的会话。对比场景先真实推荐两门课程，再利用历史卡片逐一查询详情；这一阶段尚未同步演示课程关键词索引，因此该脚本场景不代表独立名称搜索通过。后续名称索引补齐和日常环境验证见文末。

新增场景覆盖适配判断、资料未提供的答疑与就业保证、两门推荐课程的对比、价格和有效期及详情入口追问、需求不足时澄清，以及法语课程无匹配。自动检查协议、卡片业务数据和历史；回答是否有资料依据仍须逐条审阅，报告保留 `guide_review_required`，不能把自动检查通过当成整体回答准确率。需求澄清不能仅靠是否包含问号判断，须审阅回答是否实际询问目标和基础。

本轮不新增商业转化埋点。推荐后详情点击、下单转化和回答准确率用于后续效果评估，当前实现与少量联调样本不能保证收入提升。
