# 缓存穿透与空值缓存 FAQ

> 演示资料：本文由 DeepSeek 依据公开的 Redis 缓存通识原创编写，仅用于天机学堂 AI 能力演示，不是任何真实售卖课程的官方讲义，也不代表课程实际授课内容。核验日期：2026-10-31。

## 什么是缓存穿透

缓存穿透指查询的数据在缓存和数据库中都不存在，请求绕过缓存直接落到数据库。
攻击者用大量不存在的 key 请求时，数据库会承受无意义的查询压力。

与击穿的区别：击穿是「数据存在、缓存刚好过期」；穿透是「数据根本不存在」。
与雪崩的区别：雪崩是「大量 key 在同一时间大面积失效」。

## 空值缓存

对确认不存在的 key，可以缓存一个短期的空值标记（例如空字符串或特定占位值），
让后续同样请求先命中这个空值，不再查库。

注意点：

- 空值缓存必须有较短的过期时间，避免数据后来被创建时长期返回不存在；
- 不能把数据库异常、超时当成「不存在」写入空值，否则会把故障放大成错误结论；
- 空值 key 同样要有命名规范，避免和正常业务 key 混淆。

## 布隆过滤器

布隆过滤器可以在查库前先判断 key「可能存在」或「一定不存在」。
判断为不存在时直接返回，不再访问数据库。

限制：

- 存在误判率，判断「可能存在」不代表数据真的存在，仍需查库确认；
- 一般不支持删除，数据删除后重建过滤器要单独设计；
- 容量和误判率需要在建过滤器时估算，后期扩容成本较高。

## 接口层校验

对明显不合法的参数（如非法 ID 格式、超长字符串、负值）在入口直接拒绝，
可以减少无效请求进入缓存和数据库。参数校验不能替代空值缓存和过滤器，
它只处理格式层面的非法请求。

## 穿透、击穿、雪崩三者的区别

| 场景 | 触发条件 | 数据是否存在 | 典型处理 |
| --- | --- | --- | --- |
| 穿透 | 查询不存在的数据 | 不存在 | 空值缓存、布隆过滤器、参数校验 |
| 击穿 | 单个热点 key 过期 | 存在 | 互斥锁重建、逻辑过期 |
| 雪崩 | 大量 key 同时失效或缓存整体不可用 | 多数存在 | 过期时间打散、多级缓存、限流降级 |

三者处理思路不同：穿透解决「查不存在」，击穿解决「单点集中回源」，雪崩解决「大面积同时失效」。
